## 13.1 栈 vs 堆：两张图搞懂

> 💡 **比喻**：栈像酒店前台的快速寄存柜——小、快、后存先取（后进先出）。堆像酒店的地下行李仓库——大、慢、要拿号牌（指针）才能取。

### 栈：快速但有限

```
高地址 ┌──────────────┐
       │  ... 已有数据  │
       ├──────────────┤
       │  y = 10       │  ← 后放
       ├──────────────┤
       │  x = 5        │  ← 先取（后进先出）
       ├──────────────┤
低地址 │  ... 空闲      │
       └──────────────┘
```

栈上存放：函数参数、局部变量、`i32`/`f64`/`bool` 等大小固定的值。速度快，自动管理。

### 堆：大但需手动管理

```
堆内存（乱序分配）                栈上的指针
┌─────────┐                  ┌──────────────┐
│ "hello" │ ←─ ptr = 0x1000  │ String {     │
│  5 bytes│                  │   ptr ──┐    │
└─────────┘                  │   len=5 │    │
┌─────────┐                  │   cap=5 │    │
│  未使用  │                  │ }       │    │
└─────────┘                  └────┬────┘────┘
                                  │
                                  └──→ 指向堆上的数据
```

堆上存放：`String` 的文本数据、`Vec` 的元素、`Box` 的内容。大小不固定，通过指针访问。

> 📌 **要点**：`String` 在栈上存 3 个值（指针 ptr、长度 len、容量 cap），实际文本在堆上。移动 `String` 时只拷贝栈上这 3 个值（24 字节），不拷贝堆数据。

## 13.2 String 的内存布局

```rust
let s = String::from("hello");
```

```
栈                              堆
┌─────────────┐
│ s.ptr ──────┼─────→  ┌─────────────────┐
│ s.len = 5   │        │ h | e | l | l | o │
│ s.cap = 5   │        └─────────────────┘
│ (24字节)     │        地址 0x7f...1000
└─────────────┘
```

当 `let s2 = s;` 移动后：
```
栈                              堆
┌─────────────┐
│ s  = (已失效)│        ┌─────────────────┐
└─────────────┘        │ h | e | l | l | o │
┌─────────────┐         └─────────────────┘
│ s2.ptr ─────┼─────→   地址 0x7f...1000
│ s2.len = 5  │
│ s2.cap = 5  │
└─────────────┘
```

> ⚠️ **新手坑**：移动后 `s` 的栈数据被"标记失效"——不是清零，是编译器禁止你再访问。堆数据没动，只是换了主人。

当 `let s2 = s.clone();` 克隆后：
```
栈                              堆
┌─────────────┐               ┌─────────────────┐
│ s.ptr ──────┼──→ 0x1000    │ h | e | l | l | o │  ← 原数据
│ s.len = 5   │               └─────────────────┘
└─────────────┘
┌─────────────┐               ┌─────────────────┐
│ s2.ptr ─────┼──→ 0x2000    │ h | e | l | l | o │  ← 全新拷贝
│ s2.len = 5   │               └─────────────────┘
└─────────────┘               地址 0x7f...2000
```

## 13.3 Vec 的内存布局

```rust
let v = vec![1, 2, 3, 4, 5];
```

```
栈                              堆
┌─────────────┐
│ v.ptr ──────┼─────→  ┌───────────────────┐
│ v.len = 5   │        │  1 │  2 │  3 │  4 │  5  │
│ v.cap = 5   │        └───────────────────┘
│ (24字节)     │        5个 i32 = 20字节
└─────────────┘
```

> 💡 **比喻**：`Vec` 就像一列可以自动加车厢的火车——`len` 是当前有多少节车厢（已使用），`cap` 是铁路总长度（已分配）。当 `len == cap` 还要 push 时，自动扩容（新开一段更长的铁路，搬过去）。

### 扩容过程

```rust
let mut v = vec![1, 2, 3];
v.push(4);  // 触发扩容
```

```
扩容前（cap=3）            扩容后（cap=6）
堆                        堆（新地址）
┌───────┐                ┌───────────────────┐
│ 1│2│3 │   ──搬移──→    │ 1│2│3│4│_|_|_ │
└───────┘                └───────────────────┘
旧地址 0x1000              新地址 0x2000
                          栈上的 ptr 更新到 0x2000
```

> 📌 **要点**：`Vec` 扩容时分配新空间 → 拷贝旧数据 → 释放旧空间。借用检查器无法预知是否扩容，所以任何 `push` 之后都不允许再使用之前的引用；一旦真的扩容，数据会搬到新地址。

## 13.4 Box 的内存布局

```rust
let b = Box::new(42);
```

```
栈                    堆
┌──────────┐
│ b.ptr ───┼──→  ┌────┐
│ (8字节)   │     │ 42 │
└──────────┘     └────┘
                 地址 0x7f...3000
```

> 💡 **比喻**：`Box` 就像你在酒店前台拿了一个行李牌——牌在手里（栈），东西在仓库（堆）。你用牌去取东西，退房（离开作用域）时自动把东西从仓库取走。

为什么要把一个整数放到堆上？主要用于：
- 递归类型（如链表，大小编译时无法确定）
- 大数据避免栈拷贝
- Trait 对象（`Box<dyn Trait>`）

## 13.5 引用的内存布局

```rust
let x = 42;
let r = &x;
```

```
栈
┌──────────┐
│ x = 42   │  地址 0x100
├──────────┤
│ r = 0x100│  ← 存的是 x 的地址
└──────────┘
```

`r` 不拥有 `42`，只是"知道 `42` 住在哪"。当 `r` 离开作用域时，`42` 不会被释放——因为 `x` 才是所有者。

> 💡 **比喻**：引用就像你记了朋友的门牌号——你不拥有那个房子，但你知道怎么去。朋友搬家了（被释放了），你的门牌号就废了——这就是悬垂引用，Rust 编译器会阻止你这么做。

## 13.6 所有权移动 vs 拷贝的内存视角

### Copy（栈数据）

```rust
let x = 5;
let y = x;
```

```
栈
┌──────────┐
│ x = 5    │
├──────────┤
│ y = 5    │  ← 独立的一份拷贝
└──────────┘
```

两个独立的值，互不影响。因为 `i32` 在栈上，拷贝成本极低（4 字节）。

### Move（堆数据）

```rust
let s1 = String::from("hi");
let s2 = s1;
```

```
栈                    堆
┌──────────┐
│ s1 失效  │        ┌──────┐
├──────────┤        │ h │ i │
│ s2.ptr ──┼──→     └──────┘
│ s2.len=2 │
│ s2.cap=2 │
└──────────┘
```

`String` 的数据在堆上，如果拷贝代价可能很大（几 MB 文本）。所以 Rust 选择只拷贝栈上的指针（24 字节），转移所有权——快且安全。

> 📌 **要点**：Copy 和 Move 的选择标准很简单——如果类型实现了 `Copy` Trait（所有字段都是栈数据），就 Copy；否则就 Move。这就是为什么 `String` 是 Move 而 `i32` 是 Copy。

## 13.7 课后练习

### 基础题

**1.** 画出 `let v = vec![10, 20, 30];` 的内存布局图（栈上存什么、堆上存什么）。

<details>
<summary>参考答案要点</summary>

栈上：`v.ptr`（指向堆地址）、`v.len=3`、`v.cap=3`（共 24 字节）
堆上：`[10, 20, 30]` 三个 `i32`（共 12 字节）
`v.ptr` 指向堆上数组的起始地址。
</details>

### 进阶题

**2.** 解释为什么以下代码中 `s2` 不影响 `s1`：
```rust
let s1 = String::from("hello");
let s2 = s1.clone();
s2.push_str("!");
// s1 还是 "hello"
```

<details>
<summary>参考答案要点</summary>

`clone()` 在堆上复制了一份全新的 `"hello"` 数据，`s2.ptr` 指向新地址。修改 `s2` 只影响新地址的数据，`s1.ptr` 指向的原数据不受影响。
</details>

### 挑战题

**3.** 画出以下代码执行后的内存状态，标出哪些变量有效、哪些失效：
```rust
let s = String::from("data");
let s2 = s;
let s3 = s2.clone();
```

<details>
<summary>参考答案要点</summary>

```
栈                           堆
┌──────────┐
│ s  失效  │            ┌─────────────┐
├──────────┤            │ d|a|t|a     │ ← 原数据 (s2 指向)
│ s2.ptr ──┼──→ 0x1000  └─────────────┘
│ s2.len=4 │
│ s2.cap=4 │            ┌─────────────┐
├──────────┤            │ d|a|t|a     │ ← 克隆数据 (s3 指向)
│ s3.ptr ──┼──→ 0x2000  └─────────────┘
│ s3.len=4 │
│ s3.cap=4 │
└──────────┘
```
`s` 失效（被移动），`s2` 有效（指向原数据），`s3` 有效（指向克隆数据）。
</details>

## 13.8 Mini Project：画出你的结构体内存布局

给定这个结构体，动手画出它在栈上和堆上的完整内存布局：

```rust
struct Playlist {
    name: String,       // 栈 24 字节 + 堆若干
    tracks: Vec<String>, // 栈 24 字节 + 堆若干
    volume: u8,         // 栈 1 字节
}
```

**任务**：
1. 画出 `Playlist` 实例在栈上的样子（提示：三个字段各占多少字节？）
2. 画出 `name` 和 `tracks` 各自指向的堆数据
3. 执行 `let p2 = p1;` 后，哪些数据被移动？画出移动后的状态

<details>
<summary>参考答案</summary>

```
栈（约 49 字节，对齐到 56）
┌────────────────┐
│ name.ptr ──────┼──→ 堆: "我的歌单"（字节数 = len）
│ name.len       │
│ name.cap       │
├────────────────┤
│ tracks.ptr ────┼──→ 堆: String 数组（每个 String 又指向自己的堆）
│ tracks.len     │
│ tracks.cap     │
├────────────────┤
│ volume: 75     │
└────────────────┘
```

执行 `let p2 = p1;` 后：
- `name` 的指针/长度/容量拷贝给 `p2`，堆数据不拷贝，`p1` 失效
- `tracks` 同理——注意 `Vec<String>` 移动时只移动 Vec 的三元组，元素 String 也只是指针搬家
- `volume` 是 `u8`（Copy 类型），`p1` 和 `p2` 各有一份
</details>

> 📌 **要点**：`Vec<String>` 是"指针的指针"——栈上的 Vec 三元组指向堆上的 String 数组，每个 String 又指向自己的堆文本。画一次这个图，Move 语义就彻底通透了。

> ### 📝 记忆卡片
>
> **一句话**：String = 栈上三元组（ptr/len/cap）+ 堆上字符——Move 只搬栈上的"钥匙"。
>
> **口诀**：Clone 才复制堆，Copy 只在栈；引用只是存地址。
>
> **三个判断题**（心里过一遍）：
> 1. `let s2 = s1;`（String）会把堆上的字符数据复制一份 → ✗（只复制栈上三元组）
> 2. 64 位平台上 String 在栈上固定占 24 字节 → ✓
> 3. Vec 扩容时堆数据地址不变 → ✗（重新分配内存，地址会迁移）
